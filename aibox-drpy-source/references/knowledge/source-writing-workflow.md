## 1. 确认任务边界

先从用户输入中确定：

- 新建、修复、播放/正文、特殊内容还是分享。
- `video`、`novel`、`comic` 或 `bt`。
- 用户要求只诊断、生成草稿、保存文件、上传云剪切板还是完整真机验收。
- 是否有已有源、日志、截图、分享码或一个已正常工作的参考源。

已有源优先保留已验证的详情、目录、正文、代理、签名和动态域逻辑。不要为了重写列表而把后半链路一起替换。

## 2. 取得证据

按内容类型抓取真实阶段：

| 内容 | 必要证据 |
|---|---|
| 影视 | 首页/分类、详情、搜索、播放页或播放接口 |
| 小说 | 首页/分类、详情目录、搜索、首章与末章正文 |
| 漫画 | 列表、详情、目录、首末章图片接口与真实图片 |
| BT | 列表、详情资源、完整 magnet 或公开 torrent |

每个请求记录：

- 完整 URL 与 method。
- headers、Cookie、Referer、body/data、Content-Type。
- 分页参数和结束条件。
- 响应是 HTML、JSON、脚本、二进制还是验证页。
- 当前阶段输入 ID 来自上游哪个字段。

入口为发布页、Loading 壳或旧域 404 时，先读取 `dynamic-host-playbook.md`，确定业务域后再抓其余页面。响应出现验证码、安全验证或 HTML 挑战页时，再读取 `captcha-ocr-playbook.md`。

## 3. 站型分派

给分析结果输出明确的 `route`：

- `template`：当前 Aibox 模板展开后与目标结构吻合。
- `html`：静态 HTML 选择器能覆盖主链路。
- `hybrid`：HTML 与 API 混合，或只有个别阶段需要签名/POST/解密。
- `api`：纯 JSON、App API 或 SPA，多阶段接口相互传递 ID。

同时输出：

- `contentType`。
- `risks`：动态域、验证码、登录、签名、目录分页、图片代理、加密、JS 渲染等。
- `evidence`：支持当前判断的响应特征。
- `nextCommand`：下一步应抓取、解析、生成或检查什么。

不要仅凭网站长相选模板。先读取当前引擎模板列表，并查看模板继承展开后的真实规则。

## 4. 选择最低复杂度

固定按以下阶梯选择：

1. **模板最小覆盖**：只写 `模板`、`title`、`host` 和必要差异。
2. **字符串规则/二级字典**：用于稳定 HTML 或简单 `json:` 路径。
3. **混合规则**：列表用字符串，详情、搜索或 lazy 局部用函数。
4. **局部 async**：只把签名、POST、Cookie、动态域、聚合、解密阶段函数化。
5. **全 async**：纯 API/SPA 或所有阶段都依赖共享状态时使用。

每次升级都要写明“低一级为什么不能表达”。代码行数只作提示，不能为了短而删除错误处理、签名、动态域、分页或图片代理。

## 5. 分阶段实现

### 列表与分类

- 推荐与分类分别验证；首页有数据不能证明分类可用。
- 分类 ID 必须能被 `一级` 消费，并映射为真实接口参数。
- 筛选默认值必须存在于选项中；offset 通常由 `(pg - 1) * limit` 计算。
- 分类天然无图时允许无图，不要无证据地为每项请求详情补图。

### 详情与目录

- 影视验证全部线路；小说/漫画验证目录组数、分页和首末章。
- `vod_play_from` 与 `vod_play_url` 使用相同的 `$$$` 分组数。
- 每项必须为 `标题$地址`，并处理标题/地址中的 `#` 与 `$`。
- 下游需要多个 ID 时使用可逆组合 ID，不依赖模糊切割。

### 搜索

- 单独验证搜索 URL、method、参数名、分页和返回结构。
- 函数中从 `this.KEY` 取关键词；`searchUrl` 的 `**` 仅负责 URL 占位替换。
- POST 搜索按真实 Content-Type 构造 `body` 或 `data`。
- `searchable: 0` 时不要补假的搜索接口。

### 播放与正文

- 函数或 `js:` lazy 显式使用 `play_parse: true`；需保持 lazy 输出时使用 `play_json: []`。
- 影视验证直链、M3U8 嵌套、媒体头或明确的 `parse: 1` 行为。
- 小说返回可解析的 `novel://`，并验证首末章正文。
- 漫画返回 `pics://`，并验证首末章首尾图片文件头。
- BT 只返回完整 magnet 或公开 torrent，解析播放交给 Aibox 本地 Go 引擎。

### App API 漫画

按 `list -> detail -> catalog -> reader` 分四个阶段，不复用未经验证的 URL 或 JSON 路径。签名上下文、设备头、动态域、回退、组合章节 ID、图片代理和真机验收详见 `comic-source-development-playbook.md`。

## 6. L1/L2/L3 验收

### L1：结构证据

- 读取或解密完整源码。
- 检查 JavaScript 语法、重复键、header、模板名和模板展开。
- 检查 `*` 继承、HTML 属性 fallback、二级 `tabs/tab_text`、`this.input` 和播放契约。
- L1 只证明规则能被可靠理解，不证明站点在线可用。

### L2：单接口证据

- 对每个声明能力执行真实请求。
- 确认状态码、响应类型、关键字段和非空结果。
- 单接口失败时分类为规则、网络、反爬、鉴权、站点变化或环境问题。
- 不从别的接口拿数据冒充当前阶段成功。

### L3：完整链路证据

使用真实数据串联：

```text
class_id -> vod_id -> play_url / chapter_id -> 最终内容
```

- 不手填看起来合理的 ID。
- 首页成功但分类失败时，明确报告分类断点。
- 搜索声明可用但返回空时，明确报告搜索断点。
- 小说验证首末章；漫画验证首末章首尾图片；影视验证至少一条实际播放链。
- 检查 Aibox 引擎后处理后的最终响应，不只检查 helper 或 lazy 内部返回。

## 7. 修复与分享

- 修复前保存原始字节数、末尾和 SHA-256，先在候选补丁上完成 L1/L2/L3。
- 自动修复只修改有证据的字段，不猜测搜索地址、请求头、模板或接口。
- 小修递增 patch，功能或选择器变化递增 minor，重写递增 major。
- 保存时先写临时文件、回读校验，再原子替换；失败时保持原文件。
- 云1/云G1 上传后回读解压，核对源码字节数、末尾和 SHA-256。
- 分组分享先全量预检；任何单项失败都不能报告整组成功。
